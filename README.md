# Exam Paper Collector Bot

This bot accepts PDF documents in a private chat and copies each accepted PDF to one Telegram channel. It does not download or store papers itself; Telegram handles the file storage.

## What it does

- accepts Telegram **document** messages only when the filename ends in `.pdf` or Telegram identifies it as `application/pdf`;
- copies the PDF to the configured channel without showing the submitting user's forwarded-message attribution;
- confirms success or explains why a file was rejected;
- provides `GET /health` for Render and UptimeRobot;
- optionally allows submissions only from specified Telegram user IDs.

## 1. Create the Telegram bot and destination channel

1. In Telegram, open **@BotFather**, run `/newbot`, and save the token it gives you.
2. Create the destination channel (or use an existing one).
3. Add your bot to that channel as an **administrator** with permission to post messages.
4. Obtain the channel ID. The easiest method is to temporarily add **@userinfobot** to the channel, read the negative ID it reports (usually beginning `-100`), then remove it. You can also use `@channelusername` if the channel is public.

## 2. Put the project on GitHub

Create a new private GitHub repository, then upload the contents of this folder to its root. Keep the repository private because it represents your deployment configuration.

## 3. Deploy on Render

1. At Render, choose **New → Blueprint** and connect the GitHub repository.
2. Render detects `render.yaml`; create the service on the Free plan.
3. Set these environment variables in the service settings:

   | Variable | Value |
   | --- | --- |
   | `BOT_TOKEN` | Token from BotFather |
   | `CHANNEL_ID` | Channel numeric ID, or public `@channelusername` |
   | `WEBHOOK_SECRET` | Keep the value generated by Render, or replace with a long random secret |
   | `ALLOWED_USER_IDS` | Optional: comma-separated numeric Telegram user IDs; blank accepts everyone |

4. Copy the final service address, for example `https://exam-paper-collector.onrender.com`.

## 4. Register the Telegram webhook

In a browser, replace the three placeholders below, then open the resulting URL once:

```text
https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=https%3A%2F%2F<YOUR-RENDER-DOMAIN>%2Fwebhook&secret_token=<WEBHOOK_SECRET>
```

Telegram should return JSON with `"ok":true`. To verify the configuration, open:

```text
https://api.telegram.org/bot<BOT_TOKEN>/getWebhookInfo
```

Do not share either URL: they contain your bot token.

## 5. Keep the free service awake

Create a free HTTP(s) monitor in UptimeRobot:

- URL: `https://<YOUR-RENDER-DOMAIN>/health`
- Monitoring interval: 5 minutes

That endpoint returns a small JSON success response. Render's free web services otherwise spin down after 15 minutes with no inbound traffic. Free hosting is suitable for a personal or small-school collector, not a guaranteed production service.

## Test checklist

1. Send `/start` to the bot (it will ask for a PDF).
2. Send a PDF as a **Document** (not as a photo).
3. Confirm that it appears in the channel and the bot replies with a receipt.
4. Send a non-PDF file and confirm the bot rejects it.

## Notes

- Telegram's regular Bot API file upload limit is currently 50 MB. This bot copies the original message internally instead of uploading the PDF again.
- `copyMessage` does not include a link to the original sender, unlike message forwarding.
- The `ALLOWED_USER_IDS` option is strongly recommended if the channel should not accept public submissions.
